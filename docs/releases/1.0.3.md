# EvoPilot Dashboard v1.0.3 Release Notes

## Summary

EvoPilot Dashboard v1.0.3 is a GA immutable-deployment patch. It keeps the v1.0.0 browser product contract and the v1.0.2 artifact chain, then hardens the ECS compose template for pinned image-digest rollout.

## What Changed

- `deploy/ecs/compose.immutable.yaml` now declares the `evopilot-dashboard` compose project name so operators do not accidentally create an `ecs` project when running the template from `deploy/ecs/`.
- Release and operations docs use explicit `-p evopilot-dashboard`, `--env-file .env`, and `--no-build` commands for image-digest deployment.

## Who Should Upgrade

Upgrade if production rollout evidence must prove that ECS is running the exact Dashboard image digest with the intended compose project, port, API URL, and service name.

## Compatibility

- Compatible EvoPilot API: v1.0.5 or later.
- API contract version: v1.
- No Dashboard data migration is required.

## Validation

- `npm run check`
- `npm run release:artifact`
- `npm run verify:release-artifact`
- GitHub Release artifact upload through `.github/workflows/release-artifacts.yml`

## Deployment Notes

For immutable ECS rollout, deploy the image reference recorded in `evopilot-dashboard-1.0.3-image-metadata.json`:

```bash
export EVOPILOT_DASHBOARD_IMAGE='ghcr.io/yeliang-wang/evopilot-dashboard@sha256:<digest>'
docker compose -p evopilot-dashboard --env-file .env -f deploy/ecs/compose.immutable.yaml up -d --no-build
```

Keep the production `EVOPILOT_API_BASE_URL`, network, port, and reverse-proxy configuration under operator control.

## Rollback

Rollback to the previous Dashboard image digest or release tag, then verify Dashboard `/health`, the public HTTP entrypoint, and EvoPilot API compatibility.
