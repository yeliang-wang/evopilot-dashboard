# EvoPilot Dashboard v1.0.13 Release Notes

EvoPilot Dashboard v1.0.13 adds the browser surface for EvoPilot v1.1.8 LLM profiles: a compact management page, provider preset registration, selected-profile preflight, project default binding, and Agent Console per-run override controls.

## What Changed

- Added `LLM Profiles` to the fixed left navigation.
- Added Workspace, Project, and My Profiles tabs so operators can separate shared execution profiles from personal run overrides.
- Added a compact Register Profile modal with profile name, scope, provider preset, model, API key secret ref, and optional custom base URL.
- Added selected-profile evidence rows for profile ID, scope, provider, model, secret ref, status, project default count, last test, and server-projected usage.
- Added a real Test connection action for the selected profile and the register modal.
- Added an Agent Console LLM binding strip for project defaults and per-run user overrides.
- Added Dashboard API mappings for LLM profile list/create/preflight and project LLM binding/preflight.
- Updated documentation and static contracts so Dashboard displays EvoPilot server projections for provider, model, profile, request IDs, and token totals.

## Compatibility

- Compatible EvoPilot API: `v1.1.8` or later for LLM profile scopes, project defaults, and run overrides.
- Dashboard image: `ghcr.io/yeliang-wang/evopilot-dashboard:1.0.13`.
- Node.js: 22 or later for repository validation and local development.
- Docker Compose: v2 for generated container run directories.

## Deploy Paths

Run from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot-dashboard/v1.0.13/install.sh | bash -s -- --api-url http://127.0.0.1:19876 --dir evopilot-dashboard-run
```

Deploy the image on a cloud container service:

```bash
gcloud run deploy evopilot-dashboard \
  --image ghcr.io/yeliang-wang/evopilot-dashboard:1.0.13 \
  --port 8080 \
  --set-env-vars EVOPILOT_API_BASE_URL=https://evopilot.example.com
```

## Operator Notes

Dashboard does not store raw LLM keys. It sends profile metadata and secret refs to EvoPilot. EvoPilot remains the system of record for profile readiness, project defaults, run overrides, provider/model usage, token totals, request IDs, evidence, audit, and release decisions.

Use workspace profiles for shared project execution. Use My Profiles for one user's loop run override. A user profile is intentionally not bindable as the project default.
