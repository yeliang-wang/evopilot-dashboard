# EvoPilot Dashboard v1.0.8 Release Notes

EvoPilot Dashboard v1.0.8 is a GA code-structure and module-boundary cleanup patch. It keeps the v1.0.7 cloud deployment entrypoint, then splits the Agent Console from a large single-file React shell into controller, model, and focused component modules.

## What Changed

- Reduced `src/App.tsx` to a thin application shell that wires the controller state into the visible Dashboard layout.
- Added `src/dashboard/hooks/useAgentConsoleController.ts` for Agent Console state, API action orchestration, session handling, and page transitions.
- Added `src/dashboard/model.ts` for Dashboard types, initial state, API result extraction, harness draft shaping, and demo-state helpers.
- Added `src/dashboard/components/` modules for auth, console, stage state, evidence drawer, and admin/management pages.
- Expanded `tests/static-contract.test.mjs` to assert Dashboard module boundaries and line budgets for the shell, controller, model, and components.
- Updated readiness and maturity docs so public evidence points to the new module structure.

## Compatibility

- Compatible EvoPilot API: `v1.0.10` or later.
- Dashboard image: `ghcr.io/yeliang-wang/evopilot-dashboard:1.0.8`.
- Node.js: 22 or later for repository validation and local development.
- Docker Compose: v2 for generated container run directories.

## Deploy Paths

Run from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot-dashboard/v1.0.8/install.sh | bash -s -- --api-url http://127.0.0.1:19876 --dir evopilot-dashboard-run
```

Deploy the image on a cloud container service:

```bash
gcloud run deploy evopilot-dashboard \
  --image ghcr.io/yeliang-wang/evopilot-dashboard:1.0.8 \
  --port 8080 \
  --set-env-vars EVOPILOT_API_BASE_URL=https://evopilot.example.com
```

Build static assets:

```bash
EVOPILOT_API_BASE_URL=https://evopilot.example.com npm run build
```

## Operator Notes

Dashboard remains a browser HTTP client. EvoPilot API remains the system of record for authentication, tenant/workspace scope, projects, harness profiles, loops, evidence, audit, release decisions, and credentials.

This release does not intentionally change the visible Agent Console v2 flow. It makes the codebase easier to maintain and gives CI a static guard against re-growing `src/App.tsx`.

## Rollback

Rollback to `v1.0.7` or the previous image digest, then verify `/health`, `/api/v1/summary`, login, Agent Console project intake, evidence drawer, and release decision rendering.
